# 七七内容雷达工作流地图

## 1. 今日选题流程

用户进入工作台查看今日推荐选题。系统根据已有内容来源、默认选题池和 AI 判断生成可写方向，并为选题提供推荐理由、平台适配和后续创作入口。

## 2. 来源管理器流程

来源管理器用于沉淀可追溯的内容证据，包括行业观察、热点线索、用户手动录入的信息和后续可能接入的平台信号。来源证据用于支撑选题判断，避免无来源伪热点。

## 3. AI 生成正文流程

选题确定后，工作台进入公众号创作链路：根据标题、角度、来源证据和七七定位生成公众号正文。正文生成应优先复用已有文章生成流程，不为新入口重复造一套生成链路。

## 4. 七七语气优化流程

正文生成后进入七七语气优化。目标是去掉汇报腔和纯 AI 感，增强口语化、现场感、操盘手判断和专业表达底线。

## 5. 公众号排版流程

优化后的正文进入公众号排版预览。排版目标是适合公众号发布和人工微调，保留标题、段落、重点提示、引用和行动建议等结构。

## 6. 飞书 webhook 推送流程

飞书当前使用 webhook 推送每日内容雷达卡片。卡片包含今日优先推荐、每条选题综合分、推荐理由、来源信号、适合平台、验证状态和操作建议。

飞书推送三路必须保持一致：

- 页面测试飞书推送。
- PowerShell `npm.cmd run feishu:push`。
- Vercel Cron `/api/cron/daily-feishu`。

三路入口必须复用同一套卡片结构和线上工作台链接规则。

## 7. Vercel Cron 推送流程

Vercel Cron 每天定时触发 `/api/cron/daily-feishu`。接口校验定时任务密钥后发送飞书内容雷达卡片。定时推送用于每天早上自动提醒今日值得写的选题。

## 8. 本地 localhost 与线上 Vercel 分工

线上 Vercel 适合：

- 选题。
- 正文生成。
- 七七语气优化。
- 公众号排版预览。
- 飞书入口。
- Cron 推送。

本地 localhost 适合：

- 公众号素材上传。
- 封面 media_id 获取。
- 公众号草稿箱写入。

这条分工在 V1 阶段必须保留，不要为了线上化破坏已跑通主链路。

## 9. 公众号草稿箱写入流程

当前推荐在本地 localhost 完成公众号封面上传、素材处理和草稿箱写入。用户完成排版和内容检查后，再进入公众号后台人工微调发布。

## 10. 为什么不能稳定线上直写公众号

微信公众号接口受 IP 白名单影响。Vercel 普通部署通常没有固定出口 IP，微信看到的是 Vercel 出口 IP，不是用户本机公网 IP，因此线上调用公众号素材上传和草稿箱写入可能被拦截。

若后续要彻底线上化，需要固定 IP 云服务、固定出口代理或其他可控出口方案。在此之前，不应把线上公众号草稿箱写入作为核心验收项。
## 11. 七七灵感池 V1 流程

灵感池是内容雷达上游输入入口，用于记录日常操盘观察、客户沟通灵感、女性健康内容想法和可延展的公众号切入点。

V1 只使用浏览器 localStorage，稳定 key 为 `qiqi_inspiration_pool_v1`，不接数据库、不接飞书同步、不做 AI 评分、不接真实平台来源。

基础流程：

1. 用户在首页进入“七七灵感池”。
2. 手动填写灵感标题、内容、类型、标签、来源/场景和备注。
3. 点击“保存到灵感池”后写入 localStorage，并在列表中展示。
4. 用户可按类型筛选灵感，可复制、归档或删除。
5. 点击“转成公众号选题”后，将该灵感转换为现有 `selectedHotspot` / `selectedTopic` 状态，继续复用当前生成大纲、生成正文、七七语气优化、公众号排版和后续发布检查流程。

边界：

- 灵感池内容是用户手动记录的创作素材，不代表真实平台热点。
- 不新增文章生成链路。
- 不影响今日选题、来源管理器、飞书推送、Vercel Cron、本地公众号草稿箱写入。

## 12. 七七灵感池 UX-FIX 流程

v3.3-1B-UX-FIX 将灵感池主入口改为倾倒式灵感收件箱。

流程：

1. 原始灵感：用户把客户聊天、项目复盘、行业观察、内容想法直接输入到大文本框。
2. AI 拆分：复用现有 `/api/ai` 任务链路，执行 `inspirationAnalyze`，拆成 1-5 条候选灵感。
3. 候选灵感：每条包含标题、内容、类型、标签、来源/场景、摘要、推荐用途、整理理由和 `draft` 状态。
4. 确认入池：用户可单条确认、编辑后入池、丢弃或全部确认。
5. localStorage：确认后继续保存到 `qiqi_inspiration_pool_v1`。
6. 转选题：入池灵感可写入现有 `selectedHotspot` / `selectedTopic` 状态，继续走生成大纲 / 正文流程。

边界：

- AI 拆分不代表真实平台热点，不得伪装真实数据来源。
- AI 失败时保留原始输入，并允许手动保存。
- 不新增 Provider、不接数据库、不接飞书同步、不改公众号和飞书主链路。

## 13. 灵感热点融合流程

七七真实内容资产池后续会把灵感池与今日热点 / 来源池打通，形成融合型选题与文章生产流程。

流程：

1. 今日热点 / 来源池生成。
2. 读取灵感池中高相关灵感。
3. 做热点 × 灵感 匹配评分。
4. 生成融合型选题和推荐理由。
5. 输出 matchedInspirations、whyThisTopicFitsQiqi、howToUseInArticle、conversionBridge。
6. 文章大纲标注每段建议使用的灵感、行业观察、七七判断和服务承接点。
7. 正文阶段将灵感自然改写，不直接照搬素材。

边界：

- 不把个人观察包装成真实热点。
- 不强行把所有热点都与灵感融合。
- 不改变今日选题、来源管理器、正文生成、排版、飞书推送的主链路，只是在其上补充融合层。

## v3.3-1F-FIX 灵感与今日选题轻量关联

今日热点 / 来源池生成后，工作台会读取灵感池里的有效灵感，按标题、摘要、类型、标签和推荐用途做轻量匹配，再把可结合的七七灵感展示到今日选题卡片、选题详情和文章大纲入口。

流程：
1. 今日热点 / 来源池生成
2. 读取灵感池中的 draft / topic_ready / outline_ready 灵感
3. 匹配 1-3 条相关灵感
4. 计算轻量融合分和真实性加成
5. 在今日选题卡片展示可引用灵感
6. 在大纲 / 正文阶段保留关联灵感上下文
7. 归档灵感可恢复，删除仍保持彻底删除

## v3.3-1F-ANGLE-FIX 灵感角度提炼

灵感与今日选题的关联，不再只展示“关联了某个案例”，而是先从灵感里拆出可用角度，再告诉用户这个角度为什么适合当前选题、应该放在文章哪里、承担什么作用、以及怎么自然表达。

流程：
1. 读取灵感池中的有效灵感
2. 提炼可用角度 useAngle
3. 生成匹配原因、文章位置、文章作用、建议表达和注意事项
4. 今日选题卡片展示“可结合的七七灵感角度”
5. 进入大纲前保留角度上下文
6. 个人观察只作为背景或主观判断，不包装成真实行业数据

## v3.4-0A-PREP 飞书内容工作流入口方案

飞书每日内容雷达卡片从“通知卡片”升级为“移动端内容工作流入口”。

当前只做 webhook 卡片 + URL 跳转方案，不做飞书自建应用交互回调。

流程：
1. 飞书卡片推送 4 个推荐选题
2. 每个选题提供“选择选题 1/2/3/4”按钮
3. “记录一条灵感”按钮跳转七七灵感池
4. “打开内容雷达工作台”按钮跳转首页
5. “查看今日推荐选题”按钮跳转今日选题列表
6. 工作台通过 `view=inspiration / view=today / view=topic` 承接跳转

边界：

- webhook 只能发卡片和跳转链接，不能原地回调和实时更新状态。
- 如果要在飞书内直接完成大纲 / 正文 / 排版，需要升级为飞书自建应用。
- 本地 localhost 继续承担公众号草稿箱写入，不改变原有分工。

## v3.4-1A-FIX 飞书卡片按钮跳转

飞书每日内容雷达卡片已经开始从通知入口升级为工作流入口 V1。

当前实现重点：

1. 新增“记录一条灵感”按钮，跳转 `view=inspiration`。
2. 每条推荐选题增加“选择选题 X”按钮，跳转 `view=topic&topicIndex=n`。
3. 底部保留“打开内容雷达工作台”和“查看今日推荐选题”。
4. 页面测试、PowerShell 推送、Cron 推送复用同一套模板。

边界：

- 只做 URL 跳转，不做飞书交互回调。
- 所有跳转都必须指向公网工作台，不允许回落到 localhost。

## v3.4-0B-PREP 飞书自建应用机器人对话式工作流

如果用户希望在飞书里直接发“记录灵感：xxxx”或直接点击“选择选题 1”就推进大纲 / 正文，就必须从 webhook 升级到飞书自建应用机器人。

流程：

1. 飞书接收用户消息或卡片 action。
2. 事件订阅 route 验证 challenge 并解析消息。
3. intent router 判断是记录灵感、选择选题还是生成正文。
4. AI 任务复用现有灵感拆分、选题大纲、正文优化链路。
5. 后端状态层保存会话和灵感。
6. 机器人回复确认卡片或下一步操作。

边界：

- webhook 不能完成这个链路。
- localStorage 不能作为飞书后端状态层。
- 语音消息解析和草稿箱云端写入都应该放在更后面的版本。
