# 飞书每日内容雷达卡片工作流升级 PRD

## 目标

把当前“飞书每日内容雷达通知卡片”升级为“移动端内容工作流入口”。

飞书先承担移动端入口和任务分发，不承担复杂交互状态管理；网页工作台承担选题、生成、预览和内容生产主流程；本地 localhost 继续承担公众号素材上传和草稿箱写入。

## 角色分工

### 飞书卡片承担的角色

- 每日分发 4 个推荐选题。
- 告诉用户今天为什么值得写。
- 提供“记录灵感”“打开工作台”“查看今日推荐选题”“选择选题 1/2/3/4”的快捷入口。
- 作为移动端触发器，而不是内容生产终点。

### 线上工作台承担的角色

- 承接飞书跳转。
- 展示今日选题、灵感角度、选题详情、大纲生成、正文生成、七七语气优化、公众号排版。
- 复用现有文章生成链路，不重建一套飞书内内容生产系统。

### 本地 localhost 承担的角色

- 公众号封面上传。
- 本地素材处理。
- 草稿箱写入。

### 飞书和网页的分工

- 飞书负责“提醒 + 选择 + 跳转”。
- 网页负责“查看 + 决策 + 生成 + 预览”。
- 本地 localhost 负责“微信后台写入”。

## V1 飞书卡片定位

V1 仍然使用 webhook 卡片，不做飞书自建应用交互回调。

V1 的目标不是在飞书里直接产出文章，而是把飞书变成“打开工作台前的内容入口”。

## URL 参数设计

### 当前建议先支持

- `view=inspiration`：进入七七灵感池。
- `view=today`：进入今日选题列表。
- `view=topic&topicIndex=0`：进入第 1 个选题详情。

### 后续可扩展

- `view=outline&topicIndex=0`
- `view=article&topicIndex=0`
- `view=layout&topicIndex=0`

### 约束

- URL 参数适合 V1 跳转，不适合复杂状态。
- 当前没有数据库时，不适合依赖 URL 参数保存长期编辑状态。

## 完整工作流

### 理想流程

飞书卡片 -> 选择选题 -> 选题详情 -> 生成大纲 -> 生成公众号正文 -> 七七语气优化 -> 公众号排版 -> 本地草稿箱写入 -> 多平台矩阵内容

### V1 做到哪里

- 飞书卡片展示 4 个选题。
- 点击按钮跳转工作台指定页面。
- 工作台能打开灵感池、今日选题和单个选题详情。

### V2 做到哪里

- 工作台支持大纲、正文、排版的更完整状态串联。
- 逐步补全多平台矩阵入口。

### V3 做到哪里

- 飞书自建应用交互卡片。
- card action 回调。
- 用户身份识别。
- 状态存储。
- 真正的飞书内多步骤工作流。

## 灵感入口设计

“记录一条灵感”按钮跳转到：

`${CONTENT_RADAR_APP_URL}?from=feishu&view=inspiration`

页面行为：

- 打开工作台后自动切到七七灵感池。
- 聚焦灵感输入框。

## 选题入口设计

“选择这个选题”按钮跳转到对应选题页。

页面行为：

- 自动选中该选题。
- 展示选题详情。
- 展示来源信号。
- 展示可结合的七七灵感角度。
- 展示下一步按钮：
  - 生成大纲
  - 生成公众号正文
  - 进入公众号排版

## 多平台矩阵

公众号正文完成后，后续可扩展：

- 小红书图文
- 短视频口播稿
- 朋友圈文案
- 私域社群话术

V1 只保留路线，不做自动生成。

## 风险点

1. webhook 卡片不能原地回调服务器，不能承载复杂交互。
2. 没有数据库时，飞书按钮无法长期保存用户选择状态。
3. URL 参数适合跳转，不适合复杂状态和跨设备连续编辑。
4. 公众号草稿箱写入仍建议本地 localhost，因为微信接口受 IP 白名单限制。
5. 不允许自动发布公众号，只能写入草稿箱。
6. 如果后续要在飞书里直接操作生成流程，必须升级为自建应用交互卡片。
