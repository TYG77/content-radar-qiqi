# 飞书自建应用机器人对话式工作流 PRD

## 目标

把飞书从“每日通知卡片入口”升级为“飞书内移动端内容生产助理”。

用户可以直接在飞书里和机器人对话，完成记录灵感、选择选题、生成大纲、生成正文、延展多平台内容的连续工作流，而不是每一步都跳回网页工作台。

## 当前诊断结论

当前项目已经具备以下能力：

1. 已有 webhook 推送卡片能力。
2. 已有统一的飞书卡片构建逻辑。
3. 已有 AI 灵感拆分任务。
4. 已有选题、大纲、正文、七七语气优化、多平台矩阵生成链路。
5. 已有灵感池 localStorage 写入和选题转换逻辑。

当前项目尚不具备以下能力：

1. 没有飞书自建应用 client。
2. 没有飞书事件订阅 route。
3. 没有飞书消息接收 route。
4. 没有飞书 card action 回调 route。
5. 没有用户身份映射。
6. 没有后端状态存储。
7. 没有飞书语音消息下载与处理链路。

## webhook 与自建应用的能力差异

### webhook 能做的

- 发普通消息。
- 发卡片。
- 发按钮跳转 URL。

### webhook 不能做的

- 接收用户主动消息。
- 接收语音消息。
- 接收卡片按钮回调并原地推进流程。
- 识别用户身份并维护对话状态。
- 在飞书内完成多步骤生成流程。

### 自建应用可以补齐的

- 事件订阅。
- 消息事件处理。
- 卡片 action 回调。
- 用户身份识别。
- 状态管理。
- 语音文件下载与转写。

## 用户目标对应的真实技术路径

### 场景 1：飞书内记录灵感

用户发送“记录灵感：xxxx”或发送语音。

机器人：

- 接收消息事件。
- 识别意图。
- 语音则下载文件并转文字。
- 调用灵感拆分任务。
- 自动分类、打标签、整理用途。
- 保存到后端存储。
- 回复整理结果确认卡片。

### 场景 2：飞书内选择选题

用户点击“选择选题 1”。

机器人：

- 接收卡片 action 回调。
- 根据 `topicIndex` 或任务上下文找到对应选题。
- 结合灵感池与热点上下文。
- 生成大纲。
- 回复大纲卡片。

### 场景 3：飞书内生成正文

机器人根据确认后的大纲继续生成正文，并输出正文摘要、继续操作按钮和后续内容入口。

### 场景 4：多平台矩阵

正文确认后，继续生成小红书、短视频口播、朋友圈文案等矩阵内容。

### 场景 5：公众号草稿箱

可作为后续触发动作，但当前仍不建议自动发布。公众号草稿箱写入依旧受 IP 白名单限制，仍需要本地 localhost 或固定 IP 云服务。

## V1 / V2 / V3 功能边界

### V1

- 只做文本消息记录灵感。
- 用户发“记录灵感：xxxx”。
- 机器人回复整理结果。
- 不做语音。
- 不做卡片回调。
- 不做数据库复杂状态。
- 不动公众号写入。

### V2

- 做卡片 action 回调。
- 用户点“选择选题 1”后生成大纲卡片。
- 支持确认大纲、生成正文。
- 需要后端状态存储。

### V3

- 做语音输入。
- 处理飞书语音消息。
- 语音转文字。
- 多平台矩阵。
- 固定 IP、数据库、公众号草稿箱云端写入。

## 最小技术架构

建议新增的最小模块：

- `app/api/feishu/events/route.ts`
  - 接收飞书事件订阅。
  - 处理 URL verification / challenge。
  - 处理消息事件。

- `app/api/feishu/card-action/route.ts`
  - 接收卡片交互回调。
  - 处理选题选择、大纲确认、正文生成等 action。

- `app/lib/feishu/event-client.ts`
  - 处理飞书事件验签、消息解析、挑战响应。

- `app/lib/feishu/intents.ts`
  - 识别 `record_inspiration / choose_topic / generate_outline / generate_article / unknown`。

- `app/lib/inspiration.ts`
  - 复用灵感拆分结果结构和匹配逻辑。

- `app/lib/ai/tasks.ts`
  - 复用 `inspirationAnalyze`、`generateOutline`、`generateDraft`、`optimizeDraft`。

- `storage`
  - V1 可临时用轻量存储做验证。
  - 正式需要数据库。

## 状态存储建议

- `localStorage` 不能被飞书后端读取，所以不能用于飞书机器人状态。
- 飞书机器人要记录灵感，必须有后端存储。
- V1 如果只是验证流程，可以临时用轻量内存或 mock。
- 但在 Vercel serverless 场景下，内存不适合做稳定状态层。
- 推荐 V2 直接接 Supabase、Vercel KV、Redis 或数据库。

## 语音输入边界

飞书语音输入不能只靠一个按钮完成。

需要：

1. 接收语音消息事件。
2. 获取 `file_key` 或 `message_id`。
3. 下载语音文件。
4. 调用语音转文字服务。
5. 再进入灵感分析。
6. 写入后端存储。

因此语音能力放到 V3。

## 风险点

1. 飞书事件订阅需要公网回调和验签。
2. Vercel serverless 是否适合长期承接飞书事件，需要单独验证。
3. 没有数据库无法持久化用户灵感与对话状态。
4. 飞书语音文件下载涉及权限。
5. 公众号草稿箱仍受 IP 白名单影响。
6. 卡片回调涉及用户身份与状态管理。
7. 一次性做完整链路风险过高。

## 最小实现路线

### 先做的

1. 先做飞书事件订阅 route 的 challenge 验证。
2. 再做文本消息记录灵感。
3. 再做卡片 action 回调。
4. 再把状态层接到正式存储。

### 暂不做的

- 语音下载。
- 公众号草稿箱云端直写。
- 自动发布公众号。
- 飞书自建应用以外的外部依赖扩展。
