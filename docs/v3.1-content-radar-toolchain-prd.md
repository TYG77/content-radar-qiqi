# v3.1 陈七七77内容选题雷达全链路工具接入 PRD

## 0. PRD 一句话目标

把当前“内容选题雷达工作台”从 AI 生成内容工具，升级为：
选题来源管理 + 多模型写作 + 多内容形态生成 + 排版导出 + 发布承接 的内容生产系统。

注意：
公众号是第一优先级内容形态，但不是整个产品的唯一目标。

## 2. v3.1 要解决的问题

1. 选题来源仍主要依赖 AI 生成，缺少可管理的来源证据。
2. 公众号、小红书、短视频、朋友圈虽然能生成，但各自适合接入的工具不同。
3. 写作模型没有明确分工，DeepSeek / OpenAI / Gemini / 国内模型的任务边界未统一。
4. 公众号排版目前只是预览，还不能生成适合壹伴 / 公众号后台直接使用的排版稿。
5. 小红书图文当前只是文字方案，还没有进入配图生成、卡片排版、Canva 等环节。
6. 短视频口播稿当前能生成，但还没有完整承接“试读、修改、录制、剪辑提示”的执行链路。
7. 真实趋势源、第三方平台数据、公众号草稿箱、飞书推送都涉及权限和成本，不能直接接入。

## 5. 选题来源层工具方案

### 5.1 候选工具

1. Perplexity / OpenAI web_search

用途：
- 公开网页检索
- 来源摘要
- 找到真实讨论和趋势线索

2. 国内趋势源

候选：
- 抖音指数
- 巨量算数
- 新榜 / 新榜有数
- 星榜 / 星量数据
- 小红书观察
- 视频号观察
- 公众号同类文章观察

3. 手动导入

用途：
- 链接
- 截图
- 社群观察
- 用户灵感
- 日常刷到的选题

### 5.2 分档

| 档位 | 方案 | 风险 | 处理方式 |
|---|---|---|---|
| A 档 | 来源手动录入 + AI 选题 | 低 | 可先做本地录入和管理 |
| B 档 | 公开网页检索 / Perplexity / OpenAI web_search | 中 | 先诊断 Provider 和成本 |
| C 档 | 抖音指数、新榜、星榜、巨量算数等真实平台数据源 | 高 | 必须先确认账号权限、费用、API 可用性和合规边界 |

## 12. 推荐开发顺序

### 第一步：v3.1-1 选题来源管理器

原因：
- 风险最低
- 不需要真实 API
- 最贴近“选题要有来源”的核心需求
- 能改善首页选题质量

### 第二步：v3.1-2 壹伴排版稿导出

原因：
- 风险低
- 能直接提升公众号发布效率
- 不需要真实公众号后台

### 第三步：v3.1-3 Gemini Provider 接入

原因：
- 能提升公众号长文质量
- 但涉及 Provider，必须先诊断再接入

### 第四步：小红书 / 短视频链路增强

原因：
- 当前已可生成，但还不是完整执行链路
- 等公众号主链路更稳定后再做

## 13. 风险等级说明

| 风险等级 | 定义 | 示例 | 处理方式 |
|---|---|---|---|
| A | 本地页面、文档、手动输入，无外部 API | 来源管理器、壹伴排版稿 | 可直接小步开发 |
| B | 涉及模型 Provider、结构化输出、文件处理 | Gemini 接入、语音转文字 | 先诊断，再执行 |
| C | 涉及真实平台、账号权限、费用、发布 | 抖音指数 API、公众号草稿箱、飞书推送 | 必须先 PRD 和人工确认 |

## 14. 明确不做范围

本阶段不做：

1. 自动抓取小红书 / 视频号 / 抖音真实热榜
2. 绕过平台限制的爬虫
3. 真实公众号后台同步
4. 真实发布
5. 真实图片生成
6. 付费第三方数据平台自动接入
7. API Key 管理后台
8. 用户系统
9. 计费系统
10. 飞书真实推送
11. 壹伴真实 API 对接
12. 自动剪辑或自动发布视频
